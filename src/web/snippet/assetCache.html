Shared by every host with caching on. When it's full, the least recently used files are dropped. The cache is kept in memory only and starts empty after Zoraxy restarts.
Files are stored only if the upstream allows it: responses marked no-store, no-cache or private, responses that set a cookie, and error responses are always passed through.
Cached files are shared between everyone who can reach this host (after Zoraxy's access rules and authentication). If the app itself protects some files with its own login, make sure it marks them private, or leave their extension out of the list.
When a cached file expires, Zoraxy asks the upstream whether it changed (using its ETag or Last-Modified) and keeps the stored copy if it didn't.
Responses show X-Zoraxy-Cache: HIT, REVALIDATED, MISS or BYPASS, visible in the browser's developer tools.
A browser hard reload fetches files from the upstream again. Virtual directories and WebSocket connections are never cached. Video seeking (range requests) is served from the cache only after the whole file has been stored once.
