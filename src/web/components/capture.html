Traffic Capture

Record traffic through the proxy on this node as a capture file for Wireshark (pcapng). Waymark records what it receives and sends, so HTTPS is shown decrypted.

Captures contain everything that passes through: passwords, cookies, tokens and personal data. Files stay on this node, readable only by Waymark's user, and are deleted after 24 hours. Hiding credentials removes the Authorization and Cookie headers, not data in request bodies.

Reading a capture

Open the file in Wireshark. Each HTTP request and its response is its own TCP conversation, in HTTP/1.1 form even if HTTP/2 or HTTP/3 was used; filter with http, or use Statistics > Conversations.
Decrypted HTTPS is shown on port 80 so Wireshark decodes it as HTTP. The first packet of each conversation has a comment with the real addresses and ports (filter frame.comment, or add it as a column).
Bodies longer than the limit are cut; the message then has an X-Waymark-Capture header saying how much was kept.
Stream proxies are recorded as they pass, byte for byte, on their real ports. Only connections that start while the capture runs are recorded.
The packets are built from what Waymark sent and received: TCP handshakes, sequence numbers and timing below the application are made up, so this is not the tool for network-level problems (retransmissions, MTU).
WebSocket and other upgraded connections: the request and the switch are recorded, the tunnel after it is not.
