High Availability

Run two Waymark instances as an active/passive pair. keepalived moves a floating IP to the healthy node with the highest priority; Waymark writes its settings and reports its health.

Cluster settings

        
The same settings go on every node; each node finds itself in the list by its own address. To set up a new node, use Copy settings here and Paste settings there once. After that, with configuration sync on, change them on the active node and the standby nodes copy them.

        
This node is a standby with configuration sync on, so its settings are copied from the active node. Changes saved here are replaced the next time the active node's configuration changes, unless you turn configuration sync off on this node (to pause it).

        

            

                

                    
                    
                

            

            
Floating IPs

            

                
AddressPrefix lengthLabel (optional)

                
            

            
            
All floating IPs move together: the active node holds every one of them, on the nodes' interface. The first one is the primary: the node addresses below must be in its subnet. Up to 16.

            
HTTP proxying listens on all addresses, so a new floating IP works straight away. A Layer 4 proxy rule (TCP/UDP) that listens on one specific floating IP can only start on the node holding it; to let it start on the standby too, set net.ipv4.ip_nonlocal_bind=1 on every node:
                
echo 'net.ipv4.ip_nonlocal_bind=1' | sudo tee /etc/sysctl.d/90-waymark-ha.conf
sudo sysctl --system

Notes

        

            
keepalived uses unicast VRRP between the listed node addresses. If a firewall sits between the nodes, allow IP protocol 112 (VRRP) between them.

            
keepalived runs only while high availability is on: turning it off here stops and disables keepalived on this node, and turning it on enables and starts it.

            
A node gives up the floating IP when Waymark's proxy listener stops answering (checked every 2 seconds; the floating IP moves within about 10 seconds), when Waymark stops, or when the machine goes down.

            
Configuration sync copies, from the active node: HTTP and Layer 4 proxy rules, redirects, access and path rules, SSO settings, certificates and keys, ACME settings and account, admin accounts and the login session key, log rotation and log output (syslog) settings, system settings and these HA settings. Statistics, logs, the Geo-IP database, plugins, static web server files and live SSO sessions stay per node.

            
A standby checks the active node every 10 seconds. When its configuration changes (and then stays the same for one check), the standby copies it and restarts Waymark to load it, which takes a few seconds. All nodes must run the same Waymark version.

            
Only the active node renews certificates automatically. "Renew now" still works on any node.
